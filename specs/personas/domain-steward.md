# Persona: Domain steward

## Role

The person accountable for a real-world domain — an integration, a clinical
system, a long-running initiative — who works inside a durable semantic
context that binds seamlessly to whatever session, agent harness, or runtime
they happen to be in. Distinct from the sovereign builder (who inhabits
contexts) and the node operator (who keeps the node trustworthy): the
steward *answers for the domain*, including to the person or agent who
inherits it next.

## Goals

- Open any session — any harness, any runtime, context root or linked
  repository — and be inside the domain's context without naming it.
- Keep the domain's authoritative surfaces (repos, wikis, tickets, runbooks)
  reachable from one stable identity that never holds a credential.
- Maintain a deliberate, stored answer to "what now" — the current-work
  head with a next safe action — distinct from derived orientation.
- See every context they steward at a glance: warmth, open loops, active
  sessions, drift — and drill into any of them like a filesystem.
- Hand the domain to another principal — human or agentic — as a defined
  operation: beacon, current work, custody transfer; not a tribal download.

## Frustrations

- Domain knowledge lives in the steward's head plus five browser tabs; the
  handoff plan is "schedule a meeting."
- Context tooling that works in one harness evaporates in the next.
- Compliance-sensitive domains (PHI, credentials) make naive capture
  dangerous, so nothing gets captured at all.
- "Where does this domain even live?" has different answers on different
  machines.
- Visibility requires remembering what to ask for; there is no way to
  simply *look around*.

## Context

- Tech comfort: high
- Usage frequency: daily across multiple domains; several harnesses and
  runtimes; enterprise and personal identities on the same machine
- Key devices: work host (split-identity domain), home node, whatever
  runtime the next session happens to be in

## Quotes

> "If I got hit by a bus — or promoted — could anyone, or anything, pick
> this domain up from what the node knows?"
